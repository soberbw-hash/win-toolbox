## Win Toolbox 是什么？

Windows 上很多常用操作不是不存在，而是散落在系统设置、旧控制面板、命令行和多个独立工具里。用户为了截图、清理临时文件、检查系统映像、导出驱动、看磁盘占用或安装常用组件，需要记住不同入口和命令。

Win Toolbox 把这些动作整理成一个中文控制台：先说明用途和影响，再执行固定操作并回显结果。它不试图替代所有专业工具，而是把高频入口、可靠系统命令和常用第三方组件放到一个一致界面中。

## 为什么做 Win Toolbox？

Windows 并不缺工具，真正缺的是一套降低决策成本的入口：

- 用户知道电脑慢，却不知道该先清临时文件、看空间还是查系统映像；
- 很多教程直接复制管理员命令，却不解释会改什么；
- 常用小工具散落在搜索引擎、网盘和软件站，来源难判断；
- 本地 AI 能不能跑，常被简化成“有显卡就行”；
- 系统维护完成后没有统一结果、耗时和日志。

Win Toolbox 希望把这些步骤变成一个连续体验：看懂电脑 → 选择最小动作 → 看到执行结果 → 必要时安装可靠组件 → 保留可排查的日志。

## 核心设计原则

### 🎯 高频动作留在第一屏

截图、清理、系统检查和空间定位不应藏在多层设置里。首页只放用户最可能立即使用的动作。

### 🗣️ 先解释，再执行

每个系统动作要有用途、风险和下一步提示。按钮不能只写 `DISM`、`powercfg` 或包 ID。

### 🧱 系统能力走固定边界

React 界面通过结构化 Tauri 命令调用 Rust，实现中明确选择目标、参数和结果类型，减少“前端拼一段管理员脚本”的风险。

### 🧩 第三方组件必须能追溯

组件中心展示来源、软件包 ID、主页和许可。Win Toolbox 是安装入口，不会把别人的软件包装成自有组件。

### 🧠 AI 优先本地、量力而行

先读取 CPU、内存和显存，再建议模型档位；不为了一个聊天框强迫用户注册云账号或把提示词上传。

### 🛟 不把大文件等同于垃圾

空间管理负责定位，删除决定留给用户。扫描结果中的项目可能是素材、模型、缓存或正在使用的应用数据。

## ✨ 功能一览

### 🏠 首页与快捷动作

- 基础区域截图；
- 一键安全清理临时目录；
- DISM 快速健康检查；
- 空间管理入口；
- 最近动作结果、耗时和错误回显；
- 机器 CPU、内存、显卡、系统与主要网络接口概览。

### 🛠️ 系统维护

| 动作          | 作用                              | 注意事项                |
| ------------- | --------------------------------- | ----------------------- |
| DISM 快速检查 | 快速判断 Windows 组件存储是否健康 | 主要为只读检查          |
| DISM 深度扫描 | 更完整地扫描系统映像              | 耗时更长，建议等待完成  |
| 驱动导出      | 把当前驱动导出到文档目录          | 适合重装或迁移前准备    |
| Windows 更新  | 打开系统更新页                    | 最终安装由 Windows 管理 |
| 应用管理      | 打开系统应用管理入口              | 卸载前确认重要数据      |
| 通知净化      | 打开通知设置                      | 不在后台擅自关闭通知    |
| 高性能模式    | 切换 Windows 电源计划             | 会提高功耗和发热        |
| 恢复平衡模式  | 回到日常电源策略                  | 重任务中切换前确认时机  |

### 💽 空间管理

- 扫描常见用户目录和应用数据热点；
- 用环形图、块状图和列表查看空间分布；
- 列出最大的 16 个热点位置；
- 从结果直接打开对应目录，再由用户决定如何处理；
- 不把“占用大”自动等同于“可以删除”。

### ⚡ 效率体验

- `Ctrl + Alt + B` 进入或退出老板键全屏遮罩；
- `Alt + Space` 打开本地 AI 灵感悬浮窗；
- 安装 Snipaste 后可使用 `F1` 截图、`F3` 贴图；
- 响应式桌面布局、启动进度和操作 Toast；
- 外观、偏好、组件说明与第三方许可集中在设置页。

> 老板键只是界面遮罩，不是安全隔离、隐私保护或防监控功能，不应用于隐藏敏感数据或绕过组织制度。

### 📊 1. 机器状态总览

启动时读取 Windows、CPU、核心数、内存、显卡/显存和主要网络接口，给空间管理、本地 AI 和维护建议提供同一份机器上下文。

### ✂️ 2. 基础截图

无需额外组件即可使用区域截图。需要贴图、历史或更强标注时，再从组件中心安装 Snipaste。

### 🧹 3. 一键临时文件清理

只处理实现中明确的临时目录，记录处理数量、释放空间、耗时和错误。不会因为某个目录很大就自动递归删除。

### 🩺 4. DISM 快速检查

先用轻量系统映像健康检查判断是否值得继续。健康时不需要为了“多做一步”盲目运行重修复。

### 🔬 5. DISM 深度扫描

对组件存储进行更完整扫描，适合系统更新、组件或系统文件异常场景；运行时间取决于机器和系统状态。

### 💾 6. 驱动导出

把当前驱动导出到用户文档目录，适合重装、迁移或重大系统调整前留档。导出不是驱动更新，也不保证旧驱动能用于其它机器。

### 🔋 7. 电源模式切换

在高性能和平衡策略之间切换，并明确提示功耗、发热和重任务时机。不是所谓“一键永久提速”。

### 🔔 8. 系统入口整理

把 Windows 更新、应用管理和通知设置等官方入口放到统一页面，不重复造一套系统设置。

### 🗺️ 9. 空间热点扫描

扫描常见用户目录与应用数据位置，展示最大的 16 个热点；支持图表和列表，但不自动删除。

### 🧩 10. 组件安装与状态

通过固定 `winget` 包 ID 检测、安装、打开、修复、更新或卸载组件，并按组件保留日志。

### 🧠 11. 硬件档位建议

根据内存、显存和处理器给出本地模型选择方向，避免低配机器直接下载过大模型。

### 💬 12. 本地 AI 对话

检测本机 Ollama 和已有模型，通过本地 `ollama run` 处理提示词，不内置云端账户。

### ⌨️ 13. AI 灵感悬浮窗

使用 `Alt + Space` 快速打开轻量入口；只有本地运行时和模型准备好后才真正可用。

### 🕶️ 14. 老板键

`Ctrl + Alt + B` 进入/退出全屏遮罩，作为视觉小功能提供，不宣称安全、隐私或反审计能力。

### ⚙️ 15. 偏好与第三方说明

设置页集中管理外观、使用习惯、第三方来源和许可，让组件中心不是一个没有归属信息的下载器。

## 🚀 3 分钟开始使用

1. 从 [Releases](https://github.com/soberbw-hash/win-toolbox/releases/latest) 下载正式版本；
2. 第一次启动先看机器总览，不要立即连续点击维护按钮；
3. 首页先尝试截图或只读系统检查；
4. 空间不足时打开空间管理，先定位再删除；
5. 系统异常时先跑 DISM 快速检查，确有问题再深度扫描；
6. 需要第三方工具时，在组件中心核对来源与许可；
7. 需要本地 AI 时，再安装 Ollama 和适合硬件的模型；
8. 操作失败时查看结果详情和组件日志，而不是重复点击。

> [!TIP]
> 把 Win Toolbox 当作“控制台”而不是“自动优化器”。它最有价值的地方是把状态、动作和结果放在一起，而不是每天无理由清理和修复。

## 🧩 组件中心

Win Toolbox 通过 Windows Package Manager（`winget`）安装和管理常用软件，并保留每个组件的来源、软件包 ID、主页和许可提示。第三方软件不是 Win Toolbox 自有组件，仍由原作者发布并适用各自条款。

| 组件                 | 用途                     | 安装来源 / 许可提示      |
| -------------------- | ------------------------ | ------------------------ |
| Qclaw 桌面助手       | 桌面 AI 助手             | 腾讯官方安装包，专有软件 |
| Honeyview            | 轻量图片与压缩包图片查看 | Bandisoft，Freeware      |
| Snipaste             | 增强截图与贴图           | Snipaste，Freemium       |
| File Converter       | 右键转换和压缩文件       | GPL-3.0                  |
| Koodo Reader         | 电子书阅读               | AGPL-3.0                 |
| Everything           | 快速文件搜索             | voidtools，专有免费软件  |
| Context Menu Manager | 管理系统右键菜单         | 开源项目                 |
| 7-Zip                | 压缩与解压               | 7-Zip 自有开源许可组合   |
| Clash Verge Rev      | 网络代理客户端           | GPL-3.0                  |
| BCUninstaller        | 增强软件卸载             | Apache-2.0               |
| PowerToys            | Windows 效率工具集       | Microsoft，MIT           |
| Ollama               | 本地模型运行时           | 以安装时官方条款为准     |

组件支持能力因上游软件而异：安装、打开、修复、更新、禁用或卸载按钮只在实现和上游安装方式允许时显示。界面会记录组件管理日志，便于排查失败。

安装第三方组件前请确认：

- `winget` 显示的软件包 ID 与发布者正确；
- 当前网络和组织策略允许下载；
- 接受对应软件的许可证、隐私政策和系统影响；
- 代理、卸载器、右键菜单管理等工具具有较高系统权限，应从可信来源安装。

### 组件状态是什么意思？

- **可用**：检测到程序入口或 `winget` 安装记录；
- **未安装**：没有检测到对应组件；
- **可修复**：`winget` 认为已安装，但常见程序入口缺失；
- **安装/更新中**：后台任务仍在运行，不要重复触发；
- **失败**：打开详细结果和日志查看上游安装器输出。

### 为什么使用 winget？

`winget` 提供明确的软件包 ID、来源和安装器生命周期，比从未知网页抓取 EXE 更容易追溯。但它也不是绝对安全保证；包发布者、版本和条款仍需用户确认。

### 哪些组件需要特别谨慎？

- 网络代理会改变流量路径；
- 卸载器可能删除应用残留；
- 右键菜单工具会改 Shell 配置；
- PowerToys 等套件包含系统级功能；
- Ollama 和模型会占用大量磁盘、内存和显存。

<a id="local-ai"></a>

## 🧠 本地 AI

Win Toolbox 不内置云端 AI 账号。AI 页面会检查本机是否存在 Ollama、是否有已下载模型，并根据当前 CPU、内存和显存给出本地模型档位建议。

工作方式：

1. 用户选择安装或自行安装 Ollama；
2. 用户自行下载本地模型；
3. Win Toolbox 通过本机 `ollama` 命令列出和运行模型；
4. 提示词交给所选本地模型处理；
5. 回答在当前桌面会话中显示。

本地运行通常意味着提示词不需要发送到第三方云 API，但所安装模型、Ollama 版本、网络下载和其它扩展仍可能有自己的行为与条款。输入敏感信息前应了解模型来源和本机环境。

### 硬件怎么选模型？

| 机器情况              | 建议方向             | 重点注意             |
| --------------------- | -------------------- | -------------------- |
| 8GB 内存、无独显      | 小参数量、短上下文   | 系统内存和响应速度   |
| 16GB 内存、集显       | 轻量 3B–7B 量化模型  | 不要同时开太多重应用 |
| 16–32GB + 8GB 显存    | 常见 7B/8B 量化模型  | 显存占用与上下文长度 |
| 32GB+ + 12GB 以上显存 | 更大模型或更长上下文 | 下载体积、功耗和散热 |

这只是方向，不是兼容承诺。模型架构、量化格式、上下文和 Ollama 版本都会改变资源需求。

### 本地不等于没有风险

模型可能生成错误命令、虚构结论或泄露输入到复制/日志流程。当前 AI 入口只返回文本，不应直接把模型回答当作管理员操作执行。

## 🧭 三条典型工作流

### 新电脑初始化

先看系统与硬件 → 安装截图/搜索/压缩等必要组件 → 导出驱动 → 根据硬件决定是否安装 Ollama。不要一次把组件中心全部安装。

### 电脑突然变慢

先看 CPU/内存和空间热点 → 关闭明显重任务 → 只清临时文件 → 系统组件出现异常迹象时再跑 DISM。Win Toolbox 不负责诊断所有性能问题，但能避免“先重装再说”。

### 准备本地 AI

查看硬件档位 → 确认磁盘空间 → 安装 Ollama → 下载一个适配模型 → 在 AI 页确认运行时和模型状态 → 用非敏感提示词测试。

<a id="safety"></a>

## 🔒 安全与数据边界

### 🛡️ 系统操作

- 前端通过 Tauri IPC 调用 Rust 实现的已知动作；
- 系统检查、清理、DISM、驱动导出和电源模式分别有固定处理路径；
- 操作结果包含成功状态、摘要、日志、耗时和必要的下一步提示；
- 需要管理员权限的动作应由 Windows 权限机制决定；
- 空间扫描只用于定位热点，不自动删除扫描结果中的目录；
- 第三方组件通过明确的 `winget` 包 ID 管理。

### 💻 本地数据

- 系统快照读取 OS、CPU、内存、显卡和主要网络接口等设备状态；
- 组件状态、操作日志和偏好保存在本机；
- 临时文件清理只处理实现中明确选择的目标；
- 本地 AI 通过本机 Ollama 运行；
- 项目没有内置账号、云同步或广告分析系统。

提交 Issue 或截图前，请删除主机名、用户名、本机路径、公司网络名称、已安装软件清单和其它敏感信息。

### 动作风险分层

| 类型       | 示例                         | 运行前建议                       |
| ---------- | ---------------------------- | -------------------------------- |
| 只读       | 系统快照、组件状态、空间热点 | 可直接使用，仍注意截图隐私       |
| 低风险     | 打开系统设置、基础截图       | 确认目标窗口和保存位置           |
| 文件写入   | 临时清理、驱动导出、组件日志 | 关闭相关程序并检查目标路径       |
| 系统维护   | DISM、电源策略               | 保存工作，阅读结果，不要中途强关 |
| 第三方安装 | 组件安装/修复/卸载           | 核对发布者、许可、网络和组织策略 |

> [!CAUTION]
> “一键清理”和“深度修复”不是越频繁越好。对正常系统反复执行维护不会凭空增加性能，反而可能打断更新、构建或正在使用的缓存。

<a id="faq"></a>

## ❓ 常见问题

### 清理会删除我的文档吗？

一键清理针对实现中指定的临时目录，不应被理解为任意磁盘清理。任何自动清理都有边界，重要任务运行中应先关闭相关程序并备份数据。

### 空间管理为什么只显示热点，不直接删除？

目录很大不代表可以删除。项目把识别和删除分开，让用户先打开位置、判断内容和所属应用。

### 为什么 DISM 提示权限不足？

部分系统维护命令需要管理员权限。关闭当前任务后，以管理员身份启动应用并重试；受组织管理的设备请联系管理员。

### 组件安装失败怎么办？

确认 `winget` 可用、网络可访问上游源、软件包 ID 未下架，并查看组件日志。企业代理或软件限制策略可能阻止安装。

### AI 页面没有可用模型

先安装 Ollama，再至少下载一个兼容模型。Win Toolbox 只调用本机已有模型，不代替模型下载、许可证审核或硬件容量评估。

### Win Toolbox 是系统优化软件吗？

更准确地说，它是效率与维护控制台。它不承诺“一键加速”，也不会为了制造效果随意关闭服务或改注册表。

### 会后台监控我的电脑吗？

当前项目没有账号、云同步或遥测。系统快照和组件状态在用户使用界面时读取，用于显示本机状态。

### 空间扫描为什么只有 16 个热点？

界面优先展示最值得关注的位置，避免把整个文件系统变成难读列表。需要完整磁盘分析时可以安装专业工具。

### 可以删除空间热点吗？

工具只负责打开位置。请根据所属应用判断，模型、素材、工程依赖和应用数据库可能很大但不能直接删除。

### 组件是不是由 Win Toolbox 打包提供？

大多不是。组件中心通过 `winget` 使用上游包 ID，软件本体和许可属于各自权利方。

### 为什么组件显示已安装却打不开？

可能只有安装记录、入口路径变化或文件损坏。状态会标记为可修复时，可以查看日志并尝试修复。

### 能在公司电脑使用吗？

先确认组织策略。组件安装、代理、卸载器、驱动导出和电源模式可能被管理员限制。

### 本地 AI 会把内容发给云端吗？

Win Toolbox 通过本机 Ollama 命令运行模型，不内置云 API；但模型下载来源、Ollama 配置和用户安装的扩展仍需自行审核。

### 老板键能保护隐私吗？

不能。它只是视觉遮罩，不加密窗口、文件、日志或系统记录，也不能绕过监控和组织制度。

### 支持 Windows 以外的平台吗？

当前不支持。Rust 核心大量使用 Windows 命令、CIM、`winget` 和系统路径。

### 可以修改、重新打包或预装吗？

不可以默认这样做。仓库是源码可见专有软件，具体复制、分发、商用和预装边界见 [LICENSE](LICENSE)。

## 🏗️ 它是怎么工作的？

```text
React / TypeScript UI
├─ 首页、系统、组件、空间、AI 与设置页面
├─ 操作状态、进度、结果和本地偏好
└─ 通过 Tauri invoke 调用结构化命令
              │
              ▼
Rust / Tauri Core
├─ 系统快照与 Windows 命令封装
├─ 清理、DISM、驱动导出和电源策略
├─ 空间热点扫描
├─ winget 组件清单与生命周期
├─ 本机 Ollama 检测与调用
└─ 日志、结果和第三方许可信息
```

主要技术：Tauri 2、Rust、React 19、TypeScript、Vite 7、Windows PowerShell / 系统命令和 WebView2。

### Renderer

负责导航、操作进度、组件卡片、空间可视化、AI 输入和本地偏好。前端不直接读取文件系统或运行 shell。

### Tauri IPC

暴露系统快照、动作执行、组件生命周期、空间扫描、Ollama 状态和本地 AI 等结构化命令。

### Rust Core

负责 Windows 路径、进程、PowerShell、`DISM.exe`、`powercfg.exe`、`winget` 和 `ollama` 调用，并把 stdout/stderr 转成一致结果。

### 组件清单

每个组件定义 ID、名称、来源、许可、包 ID、检测路径和支持的操作。界面从清单生成状态，不维护另一份容易漂移的硬编码列表。

## 🛠️ 从源码开发

### 环境要求

- Windows 10 / 11；
- Node.js 24+ 与 npm；
- Rust stable；
- Visual Studio 2022 C++ Build Tools；
- WebView2 Runtime；
- 测试组件安装时需要 `winget`。

### 安装依赖

```powershell
git clone https://github.com/soberbw-hash/win-toolbox.git
cd win-toolbox
npm install
```

### 前端开发

```powershell
npm run dev
```

浏览器开发模式只能验证前端布局；系统快照、清理、组件管理和本地 AI 等能力需要 Tauri 环境。

### 桌面开发

```powershell
npm run tauri dev
```

### 构建

```powershell
npm run build
npm run tauri build
```

## ✅ 变更验证建议

提交前至少完成：

- `npm run build`；
- `cargo check --manifest-path src-tauri/Cargo.toml`；
- 普通权限与管理员权限启动；
- 清理目标为空、部分文件占用和权限拒绝场景；
- DISM 成功/失败回显；
- 空间扫描空目录、大目录和不可访问目录；
- `winget` 不存在、网络失败、已安装、可修复和卸载场景；
- Ollama 未安装、无模型、有模型和命令失败场景；
- 980×680 最小窗口与 1440×900 默认窗口；
- 老板键进入、退出和重复触发。

系统动作改动应在测试机或可恢复环境中验证，不要用唯一的生产设备第一次试验删除和注册表逻辑。
